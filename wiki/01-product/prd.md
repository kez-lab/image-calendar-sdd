# Product Requirements Document

## Product Summary

이 앱은 사용자가 하루의 사진, 짧은 메모, 감정 태그를 날짜별로 기록하고 캘린더와 아카이브에서 다시 볼 수 있는 개인용 이미지 캘린더다. 서버, 로그인, 친구 공유 없이 모든 데이터는 현재 디바이스 로컬에 저장된다.

## Product Promise

“내 폰 안에만 쌓이는 하루 사진 캘린더”

보조 포지셔닝:

“사진첩보다 정리되고 다이어리보다 가벼운 개인 기록 도구”

## Target Users

- 하루 1-3장의 사진을 개인적으로 기록하고 싶은 Daily Photo Keeper
- 공개형 SNS는 부담스럽지만 개인 기록은 하고 싶은 사용자
- 사진첩보다 날짜별 정리가 잘 되는 구조를 원하는 사용자
- 감성적인 다이어리 앱을 좋아하지만 복잡한 기능은 원하지 않는 20대 사용자

## Core Value

- 사진과 메모를 날짜별로 쉽고 빠르게 기록한다.
- 캘린더에서 기록 유무를 한눈에 확인한다.
- 과거의 하루를 쉽게 다시 찾는다.
- 내 폰 안에만 저장된다는 신뢰감을 준다.

## MVP Goals

- 사용자는 로그인 없이 앱을 시작할 수 있다.
- 사용자는 온보딩 후 첫 기록 만들기로 자연스럽게 진입할 수 있다.
- 사용자는 월간 캘린더에서 기록이 있는 날짜를 알아볼 수 있다.
- 사용자는 사진, 짧은 메모, 감정 태그를 빠르게 저장할 수 있다.
- 같은 날짜에 여러 개의 사진 기록을 저장할 수 있다.
- 사용자는 아카이브에서 기록을 월별, 리스트, 검색, 감정 태그 기준으로 탐색할 수 있다.
- 사용자는 설정에서 로컬 저장 구조, 백업 파일 내보내기, 전체 삭제를 이해할 수 있다.

## Non-Goals

- 서버 저장
- 로그인/계정 생성
- 친구 공유
- 공개 피드
- 좋아요, 댓글, 팔로우
- 추천 알고리즘 피드
- 실시간 동기화

## Functional Requirements

### Calendar

- 월간 캘린더를 기본 홈으로 제공한다.
- 오늘 날짜를 시각적으로 강조한다.
- 기록이 있는 날짜는 점 또는 미니 스택으로 표시한다.
- 날짜를 선택하면 해당 날짜의 기록 상세로 이동한다.

### Record Creation

- 사용자는 카메라 촬영 또는 갤러리 선택으로 사진을 추가할 수 있다.
- 사용자는 기록 날짜를 선택할 수 있다.
- 사진은 필수 입력이다.
- 기록 날짜의 기본값은 오늘이다.
- 짧은 메모는 선택 입력이다.
- 감정 태그는 선택 입력이며 MVP에서는 고정 목록에서 선택한다.
- 기록 작성은 30초 안에 완료 가능해야 한다.

### Day Detail

- 사용자는 선택한 날짜의 여러 사진 기록을 카드로 볼 수 있다.
- 각 카드에는 사진, 메모, 감정 태그가 표시된다.
- 같은 날짜의 기록은 생성 시간 오름차순으로 표시한다.
- 사용자는 기록을 수정하거나 삭제할 수 있다.
- 기록이 없는 날짜는 빈 상태 UI를 보여준다.

### Archive

- 사용자는 저장한 기록을 최근 월 우선의 월별 그룹으로 모아볼 수 있다.
- 사용자는 감정 태그로 필터링할 수 있다.
- 사용자는 메모나 날짜 기반 검색을 사용할 수 있다.

### Settings and Local Data

- 설정 화면은 로컬 저장 안내를 명확히 보여준다.
- 사용자는 백업 파일 내보내기를 시작할 수 있다.
- 데이터 가져오기/복원은 정책과 품질이 확정되기 전까지 후속 기능으로 둔다.
- 사용자는 전체 데이터 삭제를 실행할 수 있다.
- 위험한 동작은 확인 모달을 사용한다.

## UX Principles

- 서버 업로드나 외부 공유로 오해될 수 있는 UI를 만들지 않는다.
- 로컬 저장 상태가 명확해야 한다.
- 기록 작성 플로우는 짧고 직관적이어야 한다.
- 날짜별 탐색이 쉬워야 한다.
- 감성은 유지하되 사용성이 먼저 드러나야 한다.
- 삭제, 백업, 복원은 명확하고 안전하게 느껴져야 한다.

## Success Criteria

- 첫 사용자도 이 앱이 로그인/서버 없이 동작한다는 점을 이해한다.
- 사용자는 30초 안에 사진 기록을 저장할 수 있다.
- 사용자는 첫 실행 후 1분 안에 로컬 저장 구조를 이해할 수 있다.
- 사용자는 특정 날짜 기록을 10초 안에 찾을 수 있다.
- 사용자는 과거 기록을 아카이브에서 쉽게 찾을 수 있다.
- 전체 데이터 삭제 전 위험을 명확히 인지한다.

## Implications for SDD

초기 spec은 아래 순서가 적절하다.

1. 캘린더 기반 하루 기록 조회
2. 사진 기록 작성
3. 아카이브 검색/필터
4. 로컬 백업/복원
5. 설정과 데이터 안전
