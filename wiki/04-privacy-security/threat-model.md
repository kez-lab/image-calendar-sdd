# Threat Model

## Key Risks

- 사용자가 데이터가 서버에 업로드된다고 오해한다.
- 사용자가 앱 삭제 시 로컬 데이터도 사라질 수 있음을 모른다.
- 전체 데이터 삭제를 실수로 실행한다.
- 백업 파일을 안전하지 않은 위치에 보관한다.
- 가져오기 중 기존 데이터가 의도치 않게 덮어써진다.
- 사진 파일과 DB 메타데이터가 불일치한다.
- 날짜/타임존 오류로 기록이 의도와 다른 날짜에 표시된다.

## Initial Mitigations

- 온보딩과 설정에서 로컬 저장 원칙을 반복해서 설명한다.
- 내보내기/가져오기/삭제는 결과를 쉬운 말로 안내한다.
- 전체 삭제는 확인 모달을 제공한다.
- 백업 가져오기 전 파일 검증을 수행한다.
- MVP에서는 내보내기를 우선 제공하고, 가져오기/복원은 데이터 손실 정책이 확정된 뒤 제공한다.
- 기록 삭제 시 이미지 파일과 메타데이터 삭제를 트랜잭션처럼 다룬다.
- 캘린더 날짜는 로컬 날짜 기준으로 명확히 처리한다.

## Needs Decision

- 백업 파일 암호화를 MVP에 포함할지 여부
- 앱 삭제 전 백업 안내를 설정에서 얼마나 적극적으로 노출할지 여부
- 사진 원본 복사와 URI 참조 중 어떤 방식이 더 안전한지 여부
