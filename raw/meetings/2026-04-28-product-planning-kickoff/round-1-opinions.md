# Round 1 Opinions: Product Planning Kickoff

Date: 2026-04-28

## Product Lead

### Summary

제품 포지셔닝은 “SNS 없는 개인용 이미지 캘린더”로 충분히 선명하다. 차별점은 감성 다이어리가 아니라 로컬 저장 신뢰와 날짜별 사진 회고다. MVP의 핵심 성공은 기능 수가 아니라 사용자가 첫 실행부터 “내 폰 안에만 저장된다”, “30초 안에 기록된다”, “캘린더에서 다시 찾기 쉽다”를 이해하는 것이다.

### Recommendations

- 포지셔닝 문장은 “내 폰 안에만 쌓이는 하루 사진 캘린더”처럼 로컬 저장과 날짜 기반 회고를 함께 드러낸다.
- P0는 온보딩, 월간 캘린더, 기록 추가, 날짜 상세, 기본 아카이브, 설정의 로컬 저장 안내/삭제/백업까지로 잡는다.
- 아카이브는 월별 그룹 리스트, 검색, 감정 태그 필터 정도로 제한한다.
- 감정 태그는 MVP에서 고정 목록으로 시작한다.
- 기록 정렬은 날짜 상세에서 생성 시간 오름차순을 기본으로 추천한다.
- 백업/복원은 로컬 전용 앱의 신뢰 기능이므로 실제 동작으로 제공하는 쪽이 제품적으로 안전하다.
- 성공 기준은 측정 가능해야 한다. 예: 로컬 저장 구조 1분 내 이해, 첫 기록 30초 이내, 특정 날짜 탐색 10초 이내.

### Risks

- 아카이브, 검색, 백업/복원을 모두 P0로 깊게 만들면 MVP가 커질 수 있다.
- 로컬 저장 안내가 설정 화면에만 있으면 초기 신뢰 형성이 약하다.
- 기본 사진 앱과의 차별화가 약해질 수 있다.
- 백업/복원 UX가 기술적으로 보이면 부담이 된다.

### Decisions Needed

- 감정 태그 고정 목록 여부
- 아카이브 기본 화면
- 검색 범위
- 백업/복원 P0 실제 기능 여부
- 캘린더 홈 로컬 저장 배지 노출 여부

## User Advocate

### Summary

핵심 사용자는 SNS 대체 사용자가 아니라 사진첩보다 정리되고 다이어리보다 가벼운 개인 기록 도구를 원하는 사용자다. 로컬 저장은 차별점이지만, 재방문 이유는 안전함보다 오늘의 사진을 날짜 위에 쉽게 남기고 나중에 빨리 찾는 경험이어야 한다.

### Recommendations

- 1차 MVP 타깃은 “하루에 사진 1~3장을 남기고 싶은 개인 기록 사용자”로 좁힌다.
- 온보딩 직후 빈 캘린더만 보여주지 말고 `오늘 첫 사진 남기기` CTA를 강하게 제공한다.
- 로컬 저장 메시지는 Settings와 온보딩에서는 명확히, Calendar에서는 작고 조용하게 노출한다.
- 기록 작성은 사진 선택, 메모 optional, 감정 optional, 저장 흐름으로 둔다.
- 습관 형성은 streak보다 캘린더의 시각적 축적감이 중심이어야 한다.
- 리마인더는 포함하더라도 선택형 로컬 알림으로 둔다.
- 아카이브 기본은 월별 보기, 보조로 검색과 감정 필터를 제공한다.

### Risks

- 로컬 저장을 과도하게 강조하면 보안 유틸리티처럼 느껴질 수 있다.
- 데이터가 로컬에만 있다는 점은 기기 분실/앱 삭제 불안을 만든다.
- 권한 요청은 사용자가 기록 추가를 누른 시점에 해야 한다.
- 감정 태그 커스텀은 MVP 복잡도를 키운다.
- 가져오기 병합/덮어쓰기 정책이 불명확하면 데이터 손실 공포가 생긴다.

### Decisions Needed

- 1차 핵심 사용자 정의
- 첫 실행 후 바로 Calendar인지, 첫 기록 유도인지
- 메모/감정 태그 optional 여부
- 감정 태그 고정 목록 여부
- 기록 정렬 기준
- 로컬 알림 포함 여부
- 백업/복원 MVP 포함 수준
- 아카이브 기본 화면

## UX Planner

### Summary

현재 IA는 Calendar, Day Detail, Add Record, Archive, Settings로 충분히 명확하다. Calendar는 기록의 집, Add는 빠른 입력, Archive는 오래된 기록 찾기, Settings는 로컬 데이터 관리로 역할 분리하면 된다.

### Recommendations

- Calendar Home은 홈 중심이다. 기록 날짜 표시는 작은 썸네일보다는 점 또는 미니 스택을 기본으로 추천한다.
- Add UX는 사진 선택/촬영, 날짜 확인, 메모, 감정 태그, 저장의 한 화면 흐름이 적절하다.
- Add 탭과 Calendar FAB는 같은 입력 화면으로 연결되어야 한다.
- 온보딩 마지막 장은 `계정 없이, 내 폰에만 저장돼요`처럼 신뢰 문구를 명확히 전달한다.
- Day Detail은 같은 날짜의 여러 기록을 카드 리스트로 보여준다.
- 빈 날짜는 날짜 맥락에 맞는 기록 추가 CTA를 제공한다.
- Archive 기본값은 월별 그룹과 이미지 리스트/그리드가 적절하다.
- 로컬 저장 copy는 온보딩, Calendar, Add, Settings에 노출한다.

### Risks

- 날짜 셀에 사진 썸네일을 과하게 넣으면 날짜 탐색성이 떨어진다.
- Archive에 보기 전환, 검색, 태그 필터를 모두 강하게 노출하면 무거워 보인다.
- 백업/내보내기 UX를 너무 숨기면 사용자 불만이 생길 수 있다.
- Add 탭과 FAB가 중복 CTA처럼 보일 수 있다.

### Decisions Needed

- 날짜 상세 기록 정렬 기준
- 감정 태그 고정/커스텀 여부
- Archive 기본 화면
- 검색 범위
- 백업/복원 MVP 포함 수준
- Add 탭을 실제 탭 화면으로 둘지 중앙 액션으로 둘지

## Local-First Strategist

### Summary

로컬 전용 신뢰는 기능 설명이 아니라 제품 약속으로 다뤄야 한다. “서버 없음, 로그인 없음, 공유 없음”은 온보딩, 기록 추가, 설정, 백업/복원 UX 전반에서 반복 노출되어야 한다.

### Recommendations

- 온보딩 3번째 화면은 “내 폰에만 저장되는 프라이빗 기록”을 유지하고, 보조 문구에 서버 업로드/계정/공유 기능 없음도 명확히 넣는다.
- 홈 캘린더와 기록 추가 화면에는 `내 폰에만 저장됨` 배지를 노출한다.
- 금지 표현은 업로드, 동기화, 클라우드, 공유, 게시, 피드다.
- 백업은 `백업 파일 내보내기`, `백업 파일 가져오기`로 표현한다.
- 내보내기 전 “파일은 앱 밖에 저장되며 보관 위치는 사용자가 직접 선택합니다”를 안내한다.
- 가져오기는 사전 검증과 미리보기를 거친다.
- MVP 가져오기는 비어 있는 앱에만 복원 허용도 현실적이다.
- 개별 기록 삭제는 앱 내부 기록만 삭제됨을 명확히 설명한다.
- 전체 삭제는 강한 확인 절차가 필요하다.
- 설정 화면은 데이터 신뢰 센터처럼 구성한다.

### Risks

- 백업/복원 버튼이 클라우드 동기화로 오해될 수 있다.
- 앱 삭제 시 데이터가 함께 사라진다는 점을 안내하지 않으면 로컬 전용 구조가 신뢰 문제로 돌아온다.
- 가져오기 병합 정책이 불명확하면 중복/덮어쓰기/누락이 발생한다.
- 사진 원본 저장 방식에 따라 삭제 UX와 백업 안정성이 달라진다.
- 전체 삭제는 위험 영역으로 분리해야 한다.

### Decisions Needed

- 사진 저장 방식
- 백업 MVP 범위
- 백업 파일 포맷
- 가져오기 정책
- 전체 데이터 삭제 범위
- 백업 암호화 포함 여부

## Retention Planner

### Summary

소셜 기능 없이도 사용자가 돌아오는 이유는 타인의 반응이 아니라 내 기록이 쌓일수록 다시 볼 가치가 커지는 구조에 있어야 한다. 리텐션 핵심은 캘린더 누적감, 빠른 기록 습관, 과거 날짜를 쉽게 다시 찾는 아카이브 가치다.

### Recommendations

- 홈 캘린더는 리텐션의 중심이다.
- 기록 작성은 사진 선택, 메모 선택 입력, 감정 태그 선택, 저장으로 끝나야 한다.
- 일간 루프는 “오늘 아직 기록이 없어요” 같은 부드러운 빈 상태와 FAB로 충분하다.
- 주간 루프는 “이번 주 기록한 날 4일” 정도의 로컬 요약으로 제한한다.
- 아카이브는 기록이 30개 이상 쌓인 뒤 장기 리텐션 가치를 만든다.
- 로컬 저장 배지는 더 사적인 기록을 남기게 하는 복귀 장치다.
- 백업/복원은 중요하지만 완성도가 낮으면 불안 요소가 된다.

### Risks

- 소셜 기능이 없어서 초기 1~3일차 리텐션은 약할 수 있다.
- 캘린더가 비어 있으면 앱 가치가 약해 보인다.
- 아카이브/검색은 기록이 쌓인 뒤 가치가 생기므로 초기 과투자는 위험하다.
- 백업/복원/전체 삭제 UX가 기술적으로 보이면 불안하다.
- 감정 태그 커스텀은 MVP에서 복잡도를 높인다.

### Decisions Needed

- 로컬 알림 포함 여부
- 주간 요약 포함 여부
- 감정 태그 고정 목록 여부
- 아카이브 기본 화면
- 백업/복원 실제 MVP 기능 여부
