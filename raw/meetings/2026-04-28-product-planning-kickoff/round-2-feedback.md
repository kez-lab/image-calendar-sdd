# Round 2 Feedback: Product Planning Kickoff

Date: 2026-04-28

## Product Lead

### Agreements

- 핵심 포지셔닝은 “내 폰 안에만 쌓이는 하루 사진 캘린더”가 가장 강하다.
- 첫 타깃은 하루 1-3장의 사진을 기록하는 Daily Photo Keeper로 좁힌다.
- 온보딩 마지막 CTA는 첫 기록 만들기로 연결해야 한다.
- 사진은 필수, 메모와 감정 태그는 선택이 맞다.
- 업로드, 동기화, 공유, 피드, 게시 같은 단어는 MVP UI에서 배제해야 한다.
- 감정 태그는 MVP에서 고정 목록으로 시작한다.
- 아카이브 기본값은 월별 그룹이 적절하다.
- 스트릭은 제외한다.

### Objections or Corrections

- 캘린더 마커는 MVP에서는 점/미니 스택으로 확정하는 편이 좋다.
- 로컬 저장 안내는 온보딩/설정은 명확하게, Calendar/Add는 짧은 배지 수준이 적절하다.
- 백업/복원 완전 연기는 위험하지만, 가져오기 품질이 낮으면 더 큰 리스크가 된다.

### Final Decision Proposals

- 제품 약속: `내 폰 안에만 쌓이는 하루 사진 캘린더`
- MVP 타깃: 하루 1-3장 사진을 남기는 개인 기록 사용자
- 첫 사용 흐름: 온보딩 3장 후 `첫 기록 만들기`로 진입
- Add 규칙: 사진 필수, 날짜 기본값 오늘, 메모/감정 태그 선택
- Calendar 마커: 점 또는 미니 스택
- Day Detail 정렬: 생성 시간 오름차순
- Archive 기본값: 월별 그룹 리스트
- Emotion Tags: 고정 목록
- Backup/Restore: MVP에는 내보내기를 실제 기능으로 포함하고, 가져오기는 품질 보장 가능할 때만 P0에 포함
- Delete: 전체 삭제는 강한 확인 모달과 삭제 범위 명시

### Remaining Open Questions

- 가져오기를 MVP에 포함할 수 있을 만큼 안정적으로 구현할지 여부
- 고정 감정 태그 목록
- Calendar 로컬 저장 배지 노출 방식
- 백업 파일 포맷의 사용자 친화적 표현

## User Advocate

### Agreements

- 1차 타깃은 Daily Photo Keeper로 좁히는 데 동의한다.
- 온보딩 후 빈 캘린더만 보여주는 흐름은 약하다.
- 추가 플로우는 사진 필수, 메모 optional, 감정 태그 optional이 맞다.
- 로컬 저장 메시지는 필요하지만 앱 전체를 보안 제품처럼 만들면 안 된다.
- 캘린더 표시는 작은 썸네일보다는 점/미니 스택이 낫다.
- 아카이브 기본값은 월별 그룹이 적절하다.
- 감정 태그는 MVP에서 고정 목록으로 시작한다.

### Objections or Corrections

- Calendar에서는 로컬 저장 문구를 상시 강조하기보다 작은 상태 배지 정도가 적절하다.
- 날짜 상세는 오래된순이 하루 흐름을 보여주고, 아카이브/리스트는 최신순이 탐색에 유리하다.
- 백업/복원을 실제 MVP에 넣는 것은 신중해야 한다. 품질 낮은 백업/복원은 로컬 신뢰를 해친다.
- 리마인더는 MVP 필수 기능이 아니다.

### Final Decision Proposals

- 메인 포지셔닝은 `사진첩보다 정리되고 다이어리보다 가벼운 개인 기록 도구`, 보조 신뢰 카피는 `내 폰 안에만 쌓이는 하루 사진 캘린더`.
- 첫 사용자 경험은 온보딩, Calendar 홈, 빈 상태 CTA, Add 흐름으로 결정한다.
- 기록 추가 최소 완료 경로는 사진 선택/촬영, 날짜 확인, 저장이다.
- 캘린더 마커는 점/미니 스택으로 시작한다.
- 감정 태그는 고정 목록으로 시작한다.
- 날짜 상세는 오래된순, 아카이브 리스트는 최신순을 기본으로 한다.
- 백업/복원은 MVP에서 실제 구현하지 않거나, 최소한 내보내기만 먼저 검토한다.

### Remaining Open Questions

- 백업/복원 MVP 수준
- 고정 감정 태그의 구체적 목록
- 첫 기록 저장 후 피드백
- Calendar 로컬 저장 배지 노출 조건
- Add 탭 진입 방식

## UX Planner

### Agreements

- MVP 타깃은 하루 1-3장 사진을 남기는 Daily Photo Keeper다.
- 첫 사용자는 온보딩 직후 첫 기록 만들기로 유도해야 한다.
- Add flow는 사진 필수, 메모/감정 태그 선택이다.
- Calendar 날짜 표시는 점/미니 스택이 우선이다.
- Archive 기본값은 월별 그룹이고 검색/감정 필터는 보조다.
- 감정 태그는 고정 목록으로 시작한다.
- 로컬 저장 카피는 온보딩, Calendar, Add, Settings에 반복 노출해야 한다.

### Objections or Corrections

- 제품 약속은 `내 폰 안에만 쌓이는 하루 사진 캘린더`가 더 직접적이다.
- 첫 기록을 강제하면 안 되므로 `첫 기록 만들기`와 `건너뛰고 캘린더 보기`를 함께 제공한다.
- Day Detail은 오름차순, Archive는 최신순이 적합하다.
- 백업/복원은 내보내기만 MVP, 가져오기는 후속이 현실적이다.

### Final Decision Proposals

- 핵심 약속 문구는 `내 폰 안에만 쌓이는 하루 사진 캘린더`.
- 첫 사용자 흐름은 온보딩, 첫 기록 만들기 CTA, Add 화면 기본이되 건너뛰기를 제공한다.
- Add 화면은 사진 필수, 메모/감정 태그 선택.
- Calendar 기록 표시는 점/미니 스택으로 시작한다.
- Archive 기본 구조는 월별 그룹과 최신순 기록 리스트/그리드.
- Day Detail 같은 날짜 기록은 생성 시간 오름차순.
- Local copy는 짧은 문구를 사용한다.
- 삭제는 확인 모달 필수.

### Remaining Open Questions

- 내보내기만 실제 지원할지, 가져오기까지 포함할지
- Archive 기록 표현 방식
- 고정 감정 태그 목록

## Local-First Strategist

### Agreements

- `내 폰 안에만 쌓이는 하루 사진 캘린더`가 로컬 전용 신뢰를 가장 잘 전달한다.
- 첫 타깃은 Daily Photo Keeper다.
- 첫 사용자는 빈 캘린더보다 첫 기록을 만들게 해야 한다.
- Add flow는 사진 필수, 메모/감정 태그 선택이다.
- 로컬 저장 문구는 온보딩, Calendar, Add, Settings에 반복 노출해야 한다.
- 금지 표현은 업로드, 동기화, 클라우드, 공유, 게시, 피드다.
- 캘린더 표시는 점/미니 스택이 안전하다.
- Archive 기본값은 월별 그룹이다.
- 감정 태그는 고정 목록이다.
- 삭제는 강한 확인과 삭제 범위 설명이 필수다.

### Objections or Corrections

- 백업/복원 둘 다 MVP 필수로 단정하면 위험하다.
- 최소 MVP는 내보내기까지 포함하고, 가져오기는 품질 조건을 만족할 때만 포함한다.
- 가져오기를 포함한다면 병합은 피하고 단순 정책으로 제한해야 한다.
- 정렬은 목적별로 달라야 한다.

### Final Decision Proposals

- 제품 핵심 문구: `내 폰 안에만 쌓이는 하루 사진 캘린더`
- MVP 타깃: 하루 1-3장의 사진을 개인적으로 기록하는 사용자
- 저장 방식: 앱 내부 복사본 저장
- 기록 작성: 사진 필수, 메모 선택, 감정 태그 선택
- 감정 태그: MVP 고정 목록
- 캘린더 마커: 점 또는 미니 스택
- 날짜 상세 정렬: 생성 시간 오름차순
- 아카이브 정렬: 최근 월 우선, 월별 그룹 기본
- 백업 MVP: 백업 파일 내보내기 포함
- 복원 MVP: 품질 확보 시 비어 있는 앱에만 복원, 아니면 후순위
- 삭제 UX: 개별 삭제와 전체 삭제 분리

### Remaining Open Questions

- 백업 파일 포맷
- 백업 파일 암호화 MVP 포함 여부
- 가져오기 MVP 포함 여부와 정책
- 전체 삭제 시 설정 초기화 여부
- 앱 삭제 시 데이터 손실 경고 노출 수준

## Retention Planner

### Agreements

- 소셜 없는 앱의 리텐션은 누적된 개인 기록의 회수 가치에서 나와야 한다.
- 첫 사용자 타깃은 Daily Photo Keeper가 맞다.
- 온보딩은 첫 기록 생성으로 빨리 연결되어야 한다.
- 사진 필수, 메모와 감정 태그 선택이 맞다.
- 감정 태그는 MVP 고정 목록, 아카이브는 월별 그룹 기본이 적절하다.

### Objections or Corrections

- 캘린더 마커는 작은 썸네일보다는 dots/mini stacks가 MVP에 더 적합하다.
- 로컬 저장 문구는 너무 자주 반복하면 불안해 보일 수 있다.
- 백업/복원은 중요하지만 MVP 핵심 루프는 아니므로 완성도 있게 만들 수 없으면 후순위가 낫다.

### Final Decision Proposals

- 제품 약속 문구는 `사진첩보다 정리되고 다이어리보다 가벼운 개인 기록 도구`를 메인으로 제안하고, 로컬 전용 가치는 서브 카피로 보강한다.
- 첫 사용 플로우는 온보딩, 첫 사진 추가, 저장 완료, 캘린더 기록 표시로 결정한다.
- Add Flow는 사진 필수, 메모 선택, 감정 태그 선택, 날짜 기본값 오늘로 고정한다.
- 감정 태그는 MVP에서 고정 목록으로 시작한다.
- 아카이브 기본값은 월별 보기, 검색/감정 필터는 보조 기능으로 둔다.
- 리마인더와 streak는 MVP에서 제외하거나 선택형 로컬 알림만 허용한다.
- 백업/복원은 구현 품질을 보장할 수 있을 때만 MVP 포함한다.
- 삭제는 강한 확인 문구와 대상 범위를 명확히 보여준다.

### Remaining Open Questions

- 같은 날짜의 여러 기록 정렬 기준
- 첫 저장 완료 후 보상 피드백
- 로컬 저장 배지 노출 조건
- 백업/복원 구현 여력
- 아카이브 초기 빈 상태/가이드
